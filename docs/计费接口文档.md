# 计时计费 后端接口文档

> 版本：v1.0
> 客户端：Electron 桌面端（Windows / macOS）
> 服务端基址：`http://oa.feilong520.top`
> 关联方案：[计费系统技术方案.md](./计费系统技术方案.md)

本文档只描述**后端需要提供/修改的接口**。客户端对接时严格按此实现。

---

## 0. 通用约定

| 项 | 约定 |
|---|---|
| 请求方法 | 全部 `POST`（除注明 GET 外） |
| Content-Type | `application/x-www-form-urlencoded` |
| 鉴权 | `token` 作为**表单参数**提交，不走 `Authorization` 头 |
| 成功响应 | `{ "code": 0, "msg": "success", "data": { ... } }` |
| 失败响应 | `{ "code": <非0>, "msg": "错误说明", "data": null }` |
| 登录失效 | HTTP `401`，或 `code = 401` / `40101` |
| 时间 | `serverTime`、`startedAt` 等均为**毫秒级时间戳**（number） |
| 时长 | 所有时长字段单位**秒**（number） |
| data | 建议返回对象；若返回 JSON 字符串，客户端也能解析 |

业务错误码约定：

| code | 含义 | 客户端处理 |
|---|---|---|
| 0 | 成功 | 正常 |
| 401 / 40101 | 登录失效 | 回登录页 |
| 4001 | 参数错误 | 提示并打点 |
| 2001 | 余额不足 | 弹充值，禁止开始会话 |
| 2002 | 会话已失效（被顶号 / 已结算 / 超时清理） | 停止当前会话，重新 start |
| 2003 | 会话不存在 | 同 2002 |
| 2004 | 会话已达单次上限（4 小时） | 停止会话并提示 |
| 2005 | 卡密不可用（不存在 / 已用 / 过期） | 提示用户 |
| 500 | 服务异常 | 走弱网/重试逻辑 |

## 1. 接口清单

| # | 接口 | 说明 | 状态 |
|---|---|---|---|
| 1 | `POST /api/account/start` | 开启计费会话 | **新增** |
| 2 | `POST /api/account/heartbeat` | 心跳上报、按秒扣费 | **新增** |
| 3 | `POST /api/account/end` | 结束会话、按分钟取整结算 | **新增** |
| 4 | `POST /api/account/profile` | 余额查询，沿用现有 `remainingTime` 字段 | **不改** |
| 5 | `POST /api/account/recharge` | 卡密兑换，沿用现有实现 | **不改** |

除以上 3 个新接口外，**现有接口一律不动**。赠送 5 分钟由后台在首次登录时完成，客户端不调用任何发放接口。

余额字段统一使用现有 `remainingTime`（单位秒），新接口的响应也沿用该命名，避免客户端维护两套字段。

## 2. 接口详情

### 2.1 开启会话 `POST /api/account/start`

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| token | string | 是 | 登录凭证 |
| sessionId | string | 是 | 客户端生成的 UUID v4 |
| seq | number | 是 | 起始序号，固定传 `0` |

**成功响应 data**

| 字段 | 类型 | 说明 |
|---|---|---|
| sessionId | string | 服务端确认的会话 ID（与入参一致） |
| startedAt | number | 会话开始时间（ms） |
| heartbeatInterval | number | 心跳间隔，默认 `60` |
| idleTimeoutSeconds | number | 客户端空闲结束时长，默认 `300` |
| remainingTime | number \| null | 当前剩余时长（秒）；为 `null` 时客户端改用 `/api/account/profile` 读取，不能按 0 处理 |
| serverTime | number | 服务器时间（ms） |
| previousSessionClosed | boolean | 是否关闭了同账号的旧会话 |

示例：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "sessionId": "0f6b6b1e-6f0a-4f0a-9d3f-2f8c1a7b9e21",
    "startedAt": 1763510400000,
    "heartbeatInterval": 60,
    "idleTimeoutSeconds": 300,
    "remainingTime": 300,
    "serverTime": 1763510400000,
    "previousSessionClosed": false
  }
}
```

**业务规则**

1. `remainingTime <= 0` → `code=2001`，不创建会话。
2. 同一账号同时只允许一个 `active` 会话：
   - 若已存在，先把旧会话按 §2.3 规则结算并置为 `superseded`，再创建新会话，返回 `previousSessionClosed=true`。
   - 旧设备下一次心跳会收到 `2002`，据此停止并提示「账号已在其他设备开始使用」。
3. 同一 `sessionId` 重复请求：直接返回首次结果（幂等），不重复创建。
4. 写入 `usage_session`：`status=active`、`started_at=now`、`last_heartbeat_at=now`、`last_seq=0`、`charged_times=0`。

### 2.2 心跳 `POST /api/account/heartbeat`

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| token | string | 是 | 登录凭证 |
| sessionId | string | 是 | 会话 ID |
| seq | number | 是 | 递增序号，从 1 开始，每次 +1 |

**成功响应 data**

| 字段 | 类型 | 说明 |
|---|---|---|
| remainingTime | number | 扣费后的剩余秒数 |
| chargedSeconds | number | 本次心跳扣减（秒，未取整） |
| chargedTotalSeconds | number | 本会话累计扣减（秒，未取整） |
| status | string | `active` / `exhausted` / `expired` |
| shouldStop | boolean | `true` 时客户端应立即停止会话 |
| serverTime | number | 服务器时间（ms） |

**扣费规则（必须按此实现）**

```
BEGIN
  SELECT session FOR UPDATE
  -- 幂等：seq <= last_seq 直接返回当前状态，不扣费
  IF seq <= session.last_seq → 返回当前 charged_times / remaining
  -- 会话有效性
  IF session.status != 'active' → 返回 2002
  -- 单次会话上限 4 小时
  IF now - started_at >= 14400s → 结算并返回 status=expired, shouldStop=true
  -- 按服务端时间差扣费，单次封顶 120 秒（防休眠唤醒按小时扣）
  dt = min(now - last_heartbeat_at, 120)
  dt = min(dt, wallet.remaining_seconds)      -- 不扣成负数
  wallet.remaining_seconds -= dt
  session.charged_times  += dt
  session.last_heartbeat_at = now
  session.last_seq          = seq
  INSERT usage_ledger(type=0, seconds=dt, remaining_after=wallet.remaining_seconds)
  IF wallet.remaining_seconds == 0 → session.status='exhausted', shouldStop=true
COMMIT
```

**说明**

- 时间一律用**服务端当前时间**，忽略客户端时间，避免改系统时间作弊。
- 余额扣到 0 后返回 `status=exhausted`、`shouldStop=true`，客户端停止并弹充值。
- 不做取整，取整只在 §2.3 结算时执行。

### 2.3 结束会话 `POST /api/account/end`

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| token | string | 是 | 登录凭证 |
| sessionId | string | 是 | 会话 ID |
| seq | number | 是 | 最后一次心跳的序号（可为 0） |
| reason | string | 是 | `user` 手动停止 / `idle` 空闲 / `quit` 退出应用 / `exhausted` 余额耗尽 / `timeout` 服务端超时 / `superseded` 被顶号 |

**成功响应 data**

| 字段 | 类型 | 说明 |
|---|---|---|
| chargedTotalSeconds | number | 取整前累计（秒） |
| billedSeconds | number | 取整后本次计费（秒），供界面提示 |
| chargedSeconds | number | 本次结算实际扣减（秒，含最后一拍 + 取整差额） |
| remainingTime | number | 结算后剩余 |
| serverTime | number | 服务器时间（ms） |

示例：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "chargedTotalSeconds": 130,
    "billedSeconds": 180,
    "chargedSeconds": 180,
    "remainingTime": 5820,
    "serverTime": 1763510530000
  }
}
```

**结算规则（必须按此实现）**

```
BEGIN
  SELECT session FOR UPDATE
  IF session.status == 'ended' → 返回首次结算结果（幂等）
  -- 1) 补最后一次心跳区间（按秒）
  dt    = min(now - last_heartbeat_at, 120)
  used  = min(dt, wallet.remaining_seconds)
  charged = session.charged_times + used
  -- 2) 对本次会话总时长向上取整到整分钟
  rounded = ceil(charged / 60) * 60
  extra   = min(rounded - charged, wallet.remaining_seconds - used)
  -- 3) 扣款 + 落流水
  wallet.remaining_seconds -= (used + extra)
  INSERT usage_ledger(type=0, seconds=used)
  INSERT usage_ledger(type=1, seconds=extra, comment='rounding')
  UPDATE session SET status='ended', ended_at=now,
         charged_times=charged, billed_times=used+extra
COMMIT
```

**边界**

- 同一 `sessionId` 重复 end → 返回首次结果，不重复扣。
- 余额不足 → `extra` 受余额限制，不透支。
- 客户端断网未发 end → 由 §4 定时任务兜底结算，规则与本接口一致。

### 2.4 余额查询 `POST /api/account/profile`（现有，不改）

余额字段就是现有的 `remainingTime`（单位秒），**无需新增字段**：

| 字段 | 类型 | 说明 |
|---|---|---|
| remainingTime | number | 剩余总时长（秒），已含赠送与充值 |

客户端获取余额统一走这个接口，三个新接口的响应也返回同名字段，便于直接刷新界面。

---

### 2.5 卡密兑换 `POST /api/account/recharge`（现有，不改）

现有实现直接复用：

- **不需要**在响应里返回余额，客户端兑换成功后再调一次 `/api/account/profile` 刷新。
- 卡密不可用时建议返回 `code=2005`（若当前为 `500`，改成 2005 能让客户端弹出准确提示；不改也能用，只是提示会变成通用错误）。

## 3. 数据表改动

钱包余额字段已存在（接口名 `remainingTime`），**不需要改钱包表**。只需给会话表补结算字段：

```sql
ALTER TABLE usage_session
  ADD COLUMN billed_times INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '结算后计费秒（取整后）',
  MODIFY COLUMN charged_times INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '按秒累计，未取整';
```

流水 `usage_ledger.type`：`0` 心跳扣费 / `1` 结算取整 / `2` 卡密充值 / `3` 后台补偿。

## 4. 服务端定时任务

| 任务 | 频率 | 逻辑 |
|---|---|---|
| 心跳超时结算 | 每 60 秒 | 将 `status=active AND last_heartbeat_at < now-180s` 的会话按 §2.3 规则结算，`reason=timeout` |

说明：

- 客户端的「空闲 300 秒结束会话」是**主动** end；服务端 180 秒无心跳是**兜底**。两者都停止计费，不冲突。
- 崩溃、强杀、断网超过 3 分钟的会话都由该任务收口。

## 5. 客户端调用时序

```
启动 / 登录后
  └─ /api/account/profile → 读 remainingTime，展示余额

首次截图 或 开始监听
  └─ /api/account/start
       ├─ code=2001 → 弹充值，禁止使用
       └─ code=0    → 每 60s /api/account/heartbeat
                        ├─ shouldStop=true → 停止并弹充值
                        ├─ code=2002      → 停止，重新 start（或登录页）
                        └─ 成功           → 刷新余额

结束（手动 / 空闲 300s / 退出应用）
  └─ /api/account/end → 用 billedSeconds 提示「本次用时 X，扣 Y」
```

## 6. 联调自测（curl）

```bash
BASE=http://oa.feilong520.top
TOKEN=<登录拿到的 token>
DEVICE=<设备号>

# 1. 开启会话
curl -s -X POST $BASE/api/account/start \
  -d "token=$TOKEN&sessionId=test-001&seq=0"

# 2. 心跳（seq 递增）
curl -s -X POST $BASE/api/account/heartbeat \
  -d "token=$TOKEN&sessionId=test-001&seq=1"

# 3. 结束
curl -s -X POST $BASE/api/account/end \
  -d "token=$TOKEN&sessionId=test-001&seq=1&reason=user"

# 4. 余额
curl -s -X POST $BASE/api/account/profile -d "token=$TOKEN"
```

**验收用例**

| 场景 | 预期 |
|---|---|
| 余额 0 时 start | `code=2001` |
| 同一 sessionId 重复 start / end | 幂等，不重复建会话、不重复扣费 |
| 心跳间隔 130 秒后再发心跳 | 只按 120 秒扣（封顶） |
| 会话实耗 130 秒后 end | `billedSeconds=180`，扣 180 |
| 会话实耗 20 秒后 end | `billedSeconds=60` |
| 余额剩 30 秒，实耗 130 秒 | 扣 30，余额归 0，`exhausted` |
| 两设备先后 start | 旧会话被结算，旧设备心跳收到 `2002` |
| 客户端不发 end 直接退出 | 180 秒后定时任务结算，金额与正常 end 一致 |
| 单会话满 4 小时 | `status=expired`，`shouldStop=true` |
