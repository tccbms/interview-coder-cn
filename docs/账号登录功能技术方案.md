# AI 面试助手账号登录功能 技术方案（第一版·简化版）

> 版本：v2.1（简化版）
> 适用客户端：Electron 桌面端（Windows / macOS）
> 关联文档：《计费系统技术方案》
> 重要变更：**移除激活码体系，启动校验改为账号密码登录**；远程配置由独立接口 `/api/account/config` 下发

---

## 1. 第一版范围

只做两件事：

1. **登录**：校验账号密码，成功签发 token。
2. **查询用户信息**：凭 token 获取账号信息与余额。

远程配置（aiUrl / aiKey / audioKey / version / downloadUrl）由独立接口 `/api/account/config` 提供，与登录解耦。

不做（后续版本再考虑）：注册、refresh_token、修改密码、设备数量限制、图形验证码、找回密码。账号由后台/售卡渠道创建后发给用户。

## 2. 激活功能移除说明

| 现有内容 | 处理 |
|---|---|
| 激活页（输入激活码） | 删除，替换为登录页（账号 + 密码） |
| `/api/code/activate` | 不再调用，服务端可下线 |
| `/api/code/check` 启动校验 | 不再调用；远程配置改由 `/api/account/config` 独立下发 |
| `activation.json` 本地激活缓存 | 删除，改为保存登录 token 的 `auth.json` |
| `deviceId` 设备号 | **保留**，登录与拉取配置时仍上报，用于风控与后续计费 |
| 更新提示、远程 AI 配置 | **保留**，数据源从 check 改为 `/api/account/config` |

启动流程变化：

```
旧：启动 → 本地激活状态 → /api/code/check（激活+配置）→ 主窗口
新：启动 → 读本地 token → /api/account/profile（校验+用户信息）→ 主窗口
                          └─ 无 token 或校验失败 → 登录页
    进入主窗口前请求 /api/account/config → 应用远程配置 + 更新提示
```

## 3. 登录与鉴权模型（简化）

- 单 token：登录成功签发，有效期 **30 天**，过期即回登录页重新登录。
- 无 refresh_token，无自动续期；业务接口返回 401 直接清空本地 token 回登录页。
- token 由主进程用 `safeStorage` 加密后存 `userData/auth.json`，不写 localStorage，不保存密码。
- 同一账号允许在多台设备登录（第一版不限制）；计费的单会话互斥在计费功能里单独做。

## 4. 核心流程

**手动登录**

```
输入账号密码 → POST /api/account/login（带 deviceId）
  ├─ 成功：保存 token → GET /api/account/profile → 进入主窗口
  │        → POST /api/account/config → 应用远程配置、更新提示
  └─ 失败：提示「账号或密码错误」/「账号已禁用」
```

**启动静默登录**

```
启动 → 读本地 token
  ├─ 无 → 登录页
  └─ 有 → GET /api/account/profile
           ├─ 成功 → /api/account/config → 主窗口
           └─ 401 / 网络失败 → 登录页（网络失败提示「网络异常，请检查后重试」，可重试）
```

**退出登录**

```
POST /api/account/logout → 删除本地 token → 登录页
```

## 6. 接口文档

### 6.1 通用约定

- 协议：建议 HTTPS（第一版如沿用 HTTP，需知晓密码与 token 明文传输的风险）
- 请求：`application/x-www-form-urlencoded`
- 认证：**token 通过 form/query 的 `token` 参数传递**（服务端实际实现，不走 Authorization 头）；login 不需要 token，profile / logout / config 都需要
- 业务失败统一 `code=500` + `msg` 描述（如「账号密码错误」「token不存在」），客户端按 msg 是否含 token 识别登录失效
- 响应：`{ "code": 0, "msg": "success", "data": { ... } }`，`code = 0` 成功；`data` 直接是 JSON 对象，不要包成字符串
- 时间：毫秒时间戳

### 6.2 登录 `POST /api/account/login`

请求：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| account | string | 是 | 账号（用户名/手机号均可，服务端自行识别） |
| password | string | 是 | 密码 |
| deviceId | string | 是 | 设备号（沿用现有 64 位设备号） |
| deviceType | int | 是 | 固定 3 |

成功 `data`：

| 字段 | 类型 | 说明 |
|---|---|---|
| token | string | 登录凭证，有效期 30 天 |
| accountId | number | 账号 ID |
| account | string | 账号名（回显） |
| serverTime | number | 服务器时间 |

失败：

| code | 含义 |
|---|---|
| 10001 | 账号或密码错误（不区分账号不存在与密码错误，防枚举） |
| 10003 | 账号已禁用 |

服务端要求：密码 bcrypt/argon2 存储校验；连续 5 次失败锁定 15 分钟；登录接口按 IP 限流 10 次/分钟。

### 6.3 查询用户信息 `POST /api/account/profile`

请求（form）：`deviceId`、`token`。

成功 `data`：

| 字段 | 类型 | 说明 |
|---|---|---|
| accountId | number | 账号 ID |
| account | string | 账号名 |
| nickname | string | 昵称，可空 |
| trialSecondsLeft | number | 试用剩余秒（给计费用，第一版可返回 0） |
| paidSecondsLeft | number | 付费剩余秒（同上） |
| serverTime | number | 服务器时间 |

失败：`code=500, msg="token不存在"`（token 无效/过期），客户端清空本地 token 回登录页。

### 6.4 远程配置 `POST /api/account/config`

需 token（form 参数）。请求：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| deviceId | string | 是 | 设备号 |
| deviceType | int | 是 | 固定 3 |

成功 `data`：

| 字段 | 类型 | 说明 |
|---|---|---|
| aiUrl | string | AI API 地址 |
| aiKey | string | AI Key |
| audioKey | string | 语音 Key |
| version | string | 最新版本号 |
| downloadUrl | string | 最新版本下载地址 |

说明：替代原 `/api/code/check` 的配置下发职责；客户端在登录成功后与启动校验通过后各拉一次，失败不阻塞进入主窗口（沿用本地已有配置）。

### 6.5 退出登录 `POST /api/account/logout`

需 token（form 参数）。请求：`deviceId`、`token`。服务端吊销该 token，返回 `data = null`。

### 6.6 卡密充值 `POST /api/account/recharge`

个人中心使用，需 token（form 参数）。请求：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| deviceId | string | 是 | 设备号 |
| deviceType | int | 是 | 固定 3 |
| token | string | 是 | 登录 token，时长充入该账号 |
| code | string | 是 | 卡密（客户端已去空格、转大写） |

成功 `data`（客户端充值成功后会重新拉 profile 刷新余额，以下字段可选）：

| 字段 | 类型 | 说明 |
|---|---|---|
| addedSeconds | number | 本次增加的秒数 |
| trialSecondsLeft | number | 充值后试用剩余 |
| paidSecondsLeft | number | 充值后付费剩余 |

失败（`code=500`，msg 直接展示）：卡密不存在 / 已使用 / 已过期 / 已作废 / token 失效。

服务端要求：充值必须走事务（标记卡密已用 + 加时长 + 写流水），同一卡密同一账号重复提交返回「卡密已使用」，不重复加时长。

### 6.6 错误码汇总

| code | 含义 | 客户端处理 |
|---|---|---|
| 0 | 成功 | — |
| 401（HTTP）/ 40101 | token 无效或过期 | 清本地 token，回登录页 |
| 10001 | 账号或密码错误 | 提示，保留账号输入 |
| 10003 | 账号已禁用 | 提示联系客服 |
| 10007 | 账号锁定中 | 显示剩余时间 |
| 429 | 请求过于频繁 | 稍后重试 |

## 7. 库表（最小集）

### 7.1 账号表 `account`

```sql
CREATE TABLE `account` (
  `id`            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `username`      VARCHAR(32)     NOT NULL COMMENT '登录账号',
  `password_hash` VARCHAR(128)    NOT NULL COMMENT 'bcrypt/argon2',
  `nickname`      VARCHAR(64)     DEFAULT NULL,
  `status`        TINYINT         NOT NULL DEFAULT 0 COMMENT '0正常 1禁用',
  `last_login_at` DATETIME(3)     DEFAULT NULL,
  `created_at`    DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  `updated_at`    DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_username` (`username`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='账号';
```

### 7.2 登录 token 表 `account_token`（MySQL 存储，无需 Redis）

```sql
CREATE TABLE `account_token` (
  `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `token`       CHAR(64)        NOT NULL COMMENT '登录凭证，安全随机数生成',
  `account_id`  BIGINT UNSIGNED NOT NULL,
  `device_id`   VARCHAR(64)     DEFAULT NULL,
  `expires_at`  DATETIME(3)     NOT NULL COMMENT '过期时间，签发时 +30 天',
  `revoked_at`  DATETIME(3)     DEFAULT NULL COMMENT '吊销时间（退出/踢下线）',
  `created_at`  DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_token` (`token`),
  KEY `idx_account` (`account_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='登录 token';
```

使用方式：

- **校验**：`SELECT account_id FROM account_token WHERE token=? AND revoked_at IS NULL AND expires_at > NOW(3)`，查不到即 401。
- **退出登录**：`UPDATE account_token SET revoked_at=NOW(3) WHERE token=?`。
- **禁用账号 / 踢下线**：`UPDATE account_token SET revoked_at=NOW(3) WHERE account_id=?`。
- **过期清理**：MySQL 没有 TTL，过期由查询条件保证；每天定时任务删除历史过期行即可。

### 7.3 登录失败计数与限流（单实例内存即可）

- 连续 5 次失败锁定 15 分钟、IP 限流 10 次/分钟：后端单实例部署时用内存 Map + 过期时间实现即可，无需 Redis；多实例部署时再换 Redis。

## 8. 后续版本预留

- refresh_token 与自动续期（减少重新登录频率）
- 设备绑定数量限制与设备管理
- 注册 / 找回密码 / 修改密码
- 计费接口（redeem、session、heartbeat）复用本方案的 token 鉴权，错误码沿用 40101 处理
