# AI 面试助手计时计费系统 技术方案

> 版本：v1.0
> 适用客户端：Electron 桌面端（Windows / macOS）
> 关联现有能力：设备激活校验 `/api/code/check`、远程配置下发（AI 地址 / Key / 语音 Key / 版本 / 下载地址）

---

## 1. 背景

### 1.1 产品现状

- 客户端启动时通过 `/api/code/check` 做设备激活校验，服务端返回 `code=0` 才进入主窗口。
- 设备身份来自本地生成的 `deviceId`（64 位十六进制），激活状态缓存在 `activation.json`。
- 服务端在 check 响应里下发远程配置：`version`、`aiUrl`、`aiKey`、`audioKey`、`downloadUrl`，客户端据此替换 AI 与语音配置。
- 目前没有任何消费计量与余额概念，只要能通过激活，就能无限使用。

### 1.2 业务需求

1. **卡密充值**：用户购买卡密，输入后兑换成使用时长。
2. **按时长计费**：按 AI 实际服务时间扣减，用多久扣多久。
3. **试用**：新用户赠送一段试用时长（具体时长由服务端配置下发）。
4. **可运营**：卡密可批量生成、可作废、可设过期；余额可查询、可补偿。

### 1.3 计费口径

- 计时单位：**秒**。
- **对话 / 语音模式：从「开始监听」开始计时，到「停止监听」结束**（余额耗尽、异常退出也结束）。
- 截图模式：从一次截图请求开始，到本次回答结束（含追问）后 60 秒空闲结束；该规则可配置开关，默认开启，避免只截图不监听即可免费使用。
- 监听期间切到设置页、帮助页不停止计时（监听本身仍在消耗语音服务）。
- 试用与付费共用同一套计时，扣减顺序为**先试用、后付费**。

### 1.4 约束与风险

- 当前接口为 `http://` 明文，卡密与 AI Key 可被中间人抓取，**计费上线前必须切 HTTPS**。
- 客户端可被逆向，任何本地计时、本地余额都不可信；**服务端是唯一账本**。
- 现有用户只有 `deviceId`，没有账号体系，换机后无法带走余额。

## 2. 整体设计

### 2.1 设计目标

| 目标 | 说明 |
|---|---|
| 服务端权威 | 余额、扣费、卡密状态全部以服务端为准，客户端只做展示与本地倒计时 |
| 防刷 | 心跳按服务端到达时间结算、卡密一次性、试用按设备发放、单账号单会话 |
| 体验平滑 | 断网有短暂宽限；余额耗尽先答完当前回答再上锁；余额展示实时 |
| 可运营 | 卡密批次管理、作废、过期；余额补偿；消费流水可审计 |
| 可演进 | 预留账户体系，后续接在线支付、套餐、代理分销 |

### 2.3 计费核心模型

- **钱包（Wallet）**：`trial_seconds_left` + `paid_seconds_left`，单位秒。
- **会话（Session）**：一次连续使用区间，服务端记录 `started_at`、`last_heartbeat_at`、`last_seq`、`status`。
- **心跳（Heartbeat）**：客户端每 60 秒上报一次，服务端按两次心跳的真实时间差扣费，单次封顶 120 秒。
- **流水（Ledger）**：每次扣费一条记录，标明扣的是试用还是付费，用于对账与客服。

扣费伪代码：

```
dt = min(now - session.last_heartbeat_at, 120s)
trialUsed = min(dt, wallet.trial_seconds_left)
paidUsed  = dt - trialUsed
wallet.trial_seconds_left -= trialUsed
wallet.paid_seconds_left  -= paidUsed
if wallet.trial + wallet.paid == 0 → session.status = exhausted, shouldStop = true
```

### 2.4 账户系统：需不需要做？

**建议做，且从第一期就做轻量账户。** 理由：

| 维度 | 只有设备（现状） | 有账户 |
|---|---|---|
| 换电脑 / 重装 | 余额带不走，需人工迁移 | 登录即恢复 |
| 客服补偿 / 退款 | 只能按 deviceId 操作，无法核实归属 | 按账号可查可补 |
| 防重复领试用 | 换设备可重复领 | 账号 + 设备双维度控制 |
| 并发控制 | 多设备可同时使用 | 单账号单会话，可踢下线 |
| 后续支付 / 套餐 / 代理 | 难扩展 | 直接挂账户 |
| 实现成本 | 低 | 中（登录 + Token + 设备绑定） |

**轻量账户方案**：手机号 + 短信验证码登录（国内），或邮箱 + 密码（海外）；登录返回 JWT；不做复杂权限体系。钱包挂在账号上，设备只做风控与在线互斥。

**兼容现有用户**：首次登录时，服务端按 `deviceId` 查是否有历史设备余额，有则合并到新账号（一次性）；现有激活码流程保持不变，账户只负责钱包。

**如果本期坚持不做账户**：余额挂 `device_id`，表结构预留 `account_id` 字段，客服提供人工迁移工具。缺点是无法防多设备刷试用、用户换机体验差，不建议长期这样。

### 2.5 关键流程

**启动**

```
客户端 → /api/code/check（deviceId）
服务端 → code=0 + 远程配置 + 余额（试用/付费/服务器时间/心跳间隔）
客户端 → 展示余额；余额为 0 进入锁定态（可进设置与充值）
```

**开始监听 → 扣费 → 停止**

```
用户点「开始监听」
客户端 → /api/billing/session/start { sessionId, mode=conversation }
服务端 → 创建会话，返回余额；余额为 0 直接拒绝
客户端每 60s → /api/billing/heartbeat { sessionId, seq }
服务端 → 按时间差扣费，返回剩余；余额为 0 时 shouldStop=true
用户点「停止监听」/ 余额耗尽
客户端 → /api/billing/session/end { sessionId, seq }
服务端 → 补扣最后一段并关闭会话
```

**卡密充值**

```
用户输入卡密
客户端 → /api/billing/redeem { cardCode }
服务端 → 校验卡密（存在/未用/未过期/未绑定其他账号）→ 加时长 → 卡密置为已用
客户端 → 刷新余额，提示「充值 1 小时成功」
```

### 2.6 状态机

客户端（`billing.ts`）：

```
idle ──开始监听/截图──▶ starting ──成功──▶ active ──停止/余额0──▶ ending ──▶ idle
  ▲                        │失败（余额不足/网络）                    │
  └────────── locked ◀─────┴───────────────────────────────────────┘
```

服务端会话：`active → ended | exhausted | timeout`（超过 8 小时强制结束，防挂机）。

### 2.7 安全与风控

1. **HTTPS**：必须。当前 `http` 下卡密等于明文广播。
2. **服务端结算**：不信任客户端上报的时长，只按心跳到达间隔计算，单次封顶。
3. **卡密**：一次性、可绑账号、可设过期、可作废；连续失败限流（5 次/分钟）。
4. **试用**：按账号 + 设备双维度记录，同一设备只发一次。
5. **并发**：同一账号同一时刻只允许一个活跃会话，新会话开始即结束旧会话（Redis 会话锁 + 数据库双保险）。
6. **时钟篡改**：客户端倒计时使用单调时钟（`process.hrtime`），并使用服务端 `serverTime` 校正偏差。
7. **请求签名（可选增强）**：`sign = HMAC-SHA256(accountId + sessionId + seq + ts, secret)`，仅提高破解门槛，核心仍靠服务端时间结算。

### 3.1 客户端（Electron）

| `src/renderer/src/.../LockOverlay.tsx`（新增） | 余额为 0 的锁定层，只保留设置与充值 |

#### 3.1.2 会话开启规则

| 触发点 | 开始 | 结束 |
|---|---|---|
| 对话模式 / 语音监听 | 用户点「开始监听」 | 点「停止监听」、余额耗尽、退出应用 |
| 截图模式 | 截图请求发起 | 回答结束（含追问）后空闲 60 秒 |
| 追加截图 | 请求发起 | 同上，复用当前会话 |

同一时刻只允许一个会话；截图发生在监听会话中时，复用监听会话，不再新建。

#### 3.1.3 心跳与倒计时

- 心跳间隔取服务端下发 `heartbeatInterval`（默认 60s），首次会话立即发一次 start。
- 本地倒计时每秒刷新，基于「最近一次服务端余额 - 单调时钟流逝」，不是系统时间。
- 心跳失败重试 3 次（5s / 15s / 30s 退避）；持续失败进入**离线宽限**，最多 120 秒；宽限内允许继续使用但界面提示「网络异常，正在同步时长」，宽限结束仍失败则暂停 AI 功能并上锁。
- 心跳返回 `shouldStop=true`：不再发起新的 AI 请求，已完成回答正常展示，随后上锁。

#### 3.1.4 异常场景

| 场景 | 处理 |
|---|---|
| 应用崩溃 / 强杀 | 会话停留 `active`，服务端在 `idleTimeout` 后无心跳自动结束并补扣（封顶 120s） |
| 休眠 / 合盖 | 恢复后心跳，单次扣费封顶 120s，避免一次扣掉几小时 |
| 多开客户端 | 服务端单账号单会话，旧会话被结束；旧客户端收到 `session-invalidated` 后上锁 |
| 断网 | 120 秒宽限，恢复后以服务端余额为准 |
| 系统时间被改 | 用服务端 `serverTime` + 单调时钟，改系统时间无效 |
| 余额在回答中途耗尽 | 当前回答答完再停，之后上锁 |

#### 3.1.5 UI 设计

- **头部**：余额徽标 `剩余 1:23:45`，低于 5 分钟变红；点击打开充值弹窗。
- **激活页**：新增「卡密充值」输入框、当前余额、试用剩余。
- **设置 → 账户与时长**：余额明细（试用 / 付费）、兑换卡密、购买入口、最近充值记录。
- **锁定层**：余额为 0 时覆盖主内容，提供「输入卡密」「购买」两个入口，设置页仍可进入。
- **提示文案**：试用期间显示「试用剩余 4:32」，避免用户误以为已付费。

#### 3.1.6 门禁位置

门禁必须在**主进程**执行，渲染层按钮置灰只是辅助：

- 截图 / 追加截图（`shortcuts.ts`）
- 自动 / 手动出提示（`conversation.ts`）
- 开始监听（`transcription.ts`）
- 开始新的 AI 流式请求前再校验一次会话有效

### 3.2 服务端

#### 3.2.1 模块划分

| 模块 | 职责 |
|---|---|
| 账户服务 | 验证码登录、JWT 签发与校验、设备绑定、在线互斥 |
| 钱包服务 | 余额查询、试用发放、扣减、补偿 |
| 会话服务 | start / heartbeat / end、超时清理、多开处理 |
| 卡密服务 | 批次生成、兑换、作废、过期、限流 |
| 流水服务 | 每次扣费落流水，支持对账与导出 |

#### 3.2.2 心跳结算（事务内）

```
BEGIN
  SELECT * FROM usage_session WHERE session_id=? AND account_id=? FOR UPDATE
  IF status != 'active' → 返回 SESSION_ENDED
  IF seq <= last_seq → 返回上次结果（幂等）
  dt = min(now - last_heartbeat_at, heartbeatInterval * 2)
  SELECT * FROM account_wallet WHERE account_id=? FOR UPDATE
  trialUsed = min(dt, trial_seconds_left)
  paidUsed  = dt - trialUsed
  UPDATE wallet ...
  UPDATE session SET last_heartbeat_at=now, last_seq=seq, charged_seconds+=dt
  INSERT INTO usage_ledger ...
  IF 余额为 0 → session.status='exhausted'
COMMIT
```

#### 3.2.3 卡密兑换（事务内）

```
BEGIN
  SELECT * FROM recharge_card WHERE code_hash=? FOR UPDATE
  校验：存在、status=未用、expire_at > now
  校验：used_by_account 为空或等于当前账号
  UPDATE card SET status=已用, used_by_account, used_by_device, used_at
  UPDATE wallet SET paid_seconds_left = paid_seconds_left + card.seconds
  INSERT INTO recharge_log ...
COMMIT
```

#### 3.2.4 试用发放

- 触发点：首次登录（或首次 `check`）。
- 条件：该 `device_id` 从未发放过试用；该账号从未发放过试用。
- 写入 `device_trial`（device_id、account_id、granted_at），并给钱包加 `trial_seconds`。
- 试用总时长由服务端配置决定，通过 check 接口 `trialSeconds` 字段下发。

#### 3.2.5 卡密生成

- 管理后台按批次生成：面额（秒）、数量、有效期、备注。
- 编码规则：`IC-XXXX-XXXX-XXXX`，去除易混淆字符（0/O、1/I）。
- 存储：只存 `code_hash`（SHA-256）与掩码 `code_mask`（如 `IC-****-****-7F2A`）；生成时导出明文文件给运营。
- 兑换时对输入做去空格、转大写、去分隔符后哈希比对。

### 3.3 管理后台（最小功能）

- 卡密批次：生成、导出、作废、查看已用情况。
- 用户：按账号 / 设备查询余额、流水、会话记录。
- 补偿：手动加时长（记录操作人与原因）。
- 统计：日活、消耗时长、充值时长、试用转化。

## 4. 接口设计

### 4.1 通用约定

- 协议：HTTPS（强制）
- 方法：POST，`application/x-www-form-urlencoded`（与现有激活接口一致）
- 认证：登录后请求带 `Authorization: Bearer <token>`；未登录接口除外
- 响应：`{ "code": 0, "msg": "success", "data": { ... } }`
- `code === 0` 成功，其余失败，`msg` 可直接展示
- 时间：毫秒时间戳
- 新接口 `data` 直接返回 JSON 对象，不要包成字符串

### 4.2 错误码

| code | 含义 | 客户端处理 |
|---|---|---|
| 0 | 成功 | — |
| 401 | 未登录 / Token 失效 | 跳登录 |
| 1001 | 卡密不存在 | 提示 |
| 1002 | 卡密已使用 | 提示并刷新余额 |
| 1003 | 卡密已过期 | 提示 |
| 1004 | 卡密已作废 | 提示 |
| 1005 | 卡密绑定其他账号 | 提示 |
| 1006 | 兑换过于频繁 | 稍后重试 |
| 2001 | 余额不足 | 上锁 + 引导充值 |
| 2002 | 会话不存在或已结束 | 重建会话 |
| 2003 | 心跳序号重复 | 忽略，使用上次结果 |
| 2004 | 会话超时 | 重新开始会话 |
| 3001 | 账号在别处使用 | 提示并上锁 |
| 3002 | 设备数超限 | 提示解绑 |
| 429 | 请求过于频繁 | 退避重试 |

### 4.3 账户接口

#### 4.3.1 发送验证码

`POST /api/account/sms-code`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| phone | string | 是 | 手机号 |
| scene | string | 是 | `login` / `bind` |

返回：`data = null`

限流：同一手机号 60 秒 1 次，每天 10 次；同一 IP 每小时 20 次。

#### 4.3.2 登录

`POST /api/account/login`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| phone | string | 是 | 手机号 |
| code | string | 是 | 验证码 |
| deviceId | string | 是 | 设备号 |
| deviceType | int | 是 | 3 |
| deviceName | string | 否 | 如 `MacBook Pro` |

`data`：

| 字段 | 类型 | 说明 |
|---|---|---|
| token | string | JWT，有效期 7 天 |
| accountId | number | 账号 ID |
| trialSecondsLeft | number | 试用剩余 |
| paidSecondsLeft | number | 付费剩余 |
| trialSeconds | number | 试用配置总时长 |
| heartbeatInterval | number | 心跳间隔秒 |
| idleTimeoutSeconds | number | 空闲结束秒 |
| serverTime | number | 服务器时间 |

#### 4.3.3 退出登录

`POST /api/account/logout`（需 Token），返回 `data = null`。

### 4.4 计费接口

## 6. 性能要求

### 6.1 容量假设

| 指标 | 假设值 |
|---|---|
| 注册用户 | 5 万 |
| 日活 | 5,000 |
| 峰值同时监听 | 500 |
| 每会话心跳 | 1 次 / 60 秒 |
| 峰值心跳 QPS | 约 10（含重试按 3 倍冗余设计 30） |
| 卡密兑换峰值 | 20 QPS（活动时） |

### 6.2 接口性能指标

| 接口 | P95 | P99 | 可用性 |
|---|---|---|---|
| `/api/billing/heartbeat` | ≤ 50ms | ≤ 100ms | 99.95% |
| `/api/billing/session/start` | ≤ 80ms | ≤ 150ms | 99.9% |
| `/api/billing/session/end` | ≤ 80ms | ≤ 150ms | 99.9% |
| `/api/billing/redeem` | ≤ 150ms | ≤ 300ms | 99.9% |
| `/api/code/check` | ≤ 200ms | ≤ 400ms | 99.9% |
| `/api/account/login` | ≤ 300ms | ≤ 600ms | 99.9% |

### 6.3 数据库与存储

- 连接池：单实例 50 连接，按 CPU 核数调整。
- 事务尽量短：心跳结算只锁 `usage_session` 与 `account_wallet` 两行，禁止在事务内做网络调用。
- 索引要求：
  - `usage_session.uk_session` 保证幂等查询走唯一索引
  - `usage_ledger` 按 `created_at` 月分区，保留 12 个月，历史归档
  - `recharge_card.idx_status_expire` 支持过期清理任务
- 大表预估：500 并发 × 每分钟 1 条流水 ≈ 72 万条/天，必须分区 + 归档。

### 6.4 缓存策略

- 余额**不以 Redis 为准**，避免缓存与账本不一致；Redis 只缓存会话锁、幂等结果与限流计数。
- 心跳幂等结果缓存 2 分钟，重复 `seq` 直接返回，避免重复事务。
- 卡密兑换不加缓存，直接查库并加行锁。

### 6.5 可用性与降级

- 心跳失败时客户端退避重试，服务端短暂不可用不影响已经开始的会话（120 秒宽限）。
- 数据库主从：写主库，读余额可走从库（允许 1 秒延迟，展示用）。
- 发布期间采用滚动重启，心跳接口无状态，可多实例水平扩展。
- 定时任务：每分钟清理超过 `idleTimeout` 的活跃会话；每天清理过期卡密状态。

### 6.6 压测要求

- 场景：500 并发会话持续 10 分钟，心跳每秒 8~10 次。
- 验收：错误率 < 0.1%，心跳 P99 < 100ms，无重复扣费（流水与余额对账一致）。
- 对账脚本：按账号汇总 `usage_ledger.seconds` 与 `account_wallet.total_charged_seconds`，差异必须为 0。

## 7. 实施计划

| 阶段 | 内容 | 产出 |
|---|---|---|
| 一期 | 账户登录、钱包、check 扩展、卡密兑换、会话心跳、客户端余额与锁定 | 可充值与计时的最小闭环 |
| 二期 | 管理后台（卡密批次、用户流水、补偿）、HTTPS、监控告警 | 可运营 |
| 三期 | 在线支付、套餐、代理分销、发票 | 商业化 |

### 风险清单

1. 接口仍为 HTTP：上线前必须切 HTTPS，否则卡密可被抓包。
2. 客户端可被逆向：不要在前端做任何余额判断逻辑，全部以服务端为准。
3. 设备号可伪造：账户 + 设备绑定 + 单会话互斥三重限制。
4. 心跳丢失导致少扣：靠 `idleTimeout` 补扣 + 封顶 120 秒平衡体验与成本。
