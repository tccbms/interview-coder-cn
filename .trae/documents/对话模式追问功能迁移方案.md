# 对话模式追问功能迁移方案

## Context（背景）

**为什么截图模式有追问、对话模式没有：**

- 截图模式在 main 进程维护持久多轮对话历史 `conversationMessages: ModelMessage[]`（[shortcuts.ts#L89](file:///Users/hetaiyi/Desktop/my/tech/web/interview-coder-cn/src/main/shortcuts.ts)），首图 / 追加截图 / 追问三种请求都读写这同一份历史；追问（`sendFollowUpQuestion` → [ai.ts getFollowUpStream](file:///Users/hetaiyi/Desktop/my/tech/web/interview-coder-cn/src/main/ai.ts)）只是往历史末尾插一条用户文字消息再流式回答，UI 入口是 [AppStatusBar.tsx](file:///Users/hetaiyi/Desktop/my/tech/web/interview-coder-cn/src/renderer/src/coder/AppStatusBar.tsx) 的「追问问题」按钮 + 输入对话框。
- 对话模式是刻意设计的**无状态提词器**：[conversation.ts buildMessages()](file:///Users/hetaiyi/Desktop/my/tech/web/interview-coder-cn/src/main/conversation.ts) 每次现拼一条消息（最近 20 句 / 1500 字上下文 + 本次要答的句子），之前的提示卡片不回传以控制请求体积；输入通道只有对方语音和「换一个角度」重写，没有给用户自己提问留入口。

**迁移方式：** 把追问做成对话模式的一种特殊提示卡片（带 `question` 字段），完全复用现有 `HintCard` + `startHint` 流式管线（中断、代际防写、错误处理、reasoning、自动保存全部现成）。

**已确认的产品决策：** 追问一次性生效——问答内容不进入后续自动/手动提示的上下文，严格保持「提示不回传」原则。

## 实现步骤

### 1. `src/shared/conversation.ts` — HintCard 扩展

- `source` 增加 `'follow-up'`：`source: 'auto' | 'manual' | 'follow-up'`
- 新增 `question?: string`（追问的问题文本）

现有逻辑天然兼容：`onSentenceGrowing` 的撤回只针对 `source !== 'auto'` 之外的判断（`card.source !== 'auto'` 跳过）——追问卡片不会被对方继续说话撤回（它不 tied to 对方的话）。

### 2. `src/main/conversation.ts` — 核心逻辑

- **`buildMessages(fromId, toId, previous?, question?)`** 增加可选 `question` 参数：
  - 有 `question` 时在末尾追加 `【我的追问】\n${question}` 块，并注明这是用户本人的提问、请直接回答（覆盖场景预设提示里「（无需回应）」的语义）
  - 无 utterance（`toId === 0`）时省略「对方刚才说的话」块，允许纯提问
- **`startHint(card, fromId, toId, source, previous?, question?)`** 增加第 6 个参数透传给 `buildMessages`
- **新增 `requestFollowUp(question: string)`**：
  - `question` 为空直接返回；不检查页面状态（与 `requestHint` 一致，main 拥有会话，设置页 mid-call 也能追问）
  - 覆盖范围：`fromId = hintedUpTo + 1`，`toId = latest?.id ?? 0`（即所有未提示的句子，无语音时为 0）；`startHint` 内已有的 `hintedUpTo = Math.max(...)` 自然生效
  - 创建卡片：`{ source: 'follow-up', question, ... }`，调 `startHint(card, fromId, toId, 'follow-up', undefined, question)`
  - API Key 缺失时沿用 `startHint` 既有的卡片错误处理
- **`requestHint()`** 两处调整，避免出提示覆盖追问卡：
  - `current` 搜索（正在写/等待的卡）跳过 `source === 'follow-up'`
  - 「换一个角度」重写分支取最后一张**非 follow-up** 卡
- 注册 IPC：`ipcMain.handle('conversation:follow-up', (_e, question: string) => requestFollowUp(question))`

### 3. `src/preload/index.ts` — 暴露 API

```ts
sendConversationFollowUp: (question: string) =>
  ipcRenderer.invoke('conversation:follow-up', question),
```

（`MainAPI = typeof api` 自动推导类型，`preload/index.d.ts` 若只引用该类型则无需改动，实现时确认。）

### 4. `src/renderer/src/conversation/ConversationStatusBar.tsx` — UI 入口

- 在「出提示 / 停止」旁加「追问」按钮（`MessageCircle` 图标，同截图模式），始终可点（对话模式本就支持多卡并行流式）
- 内联 Dialog 仿 [AppStatusBar.tsx#L134-L162](file:///Users/hetaiyi/Desktop/my/tech/web/interview-coder-cn/src/renderer/src/coder/AppStatusBar.tsx)：`Textarea` + Ctrl/Cmd+Enter 提交 + 取消/提交按钮；提交调 `window.api.sendConversationFollowUp()`，无需 spinner（卡片自身显示 streaming/error 状态）

### 5. `src/renderer/src/conversation/HintPanel.tsx` — 卡片渲染

`HintCardView` 对 follow-up 卡：
- 头部左侧显示用户的问题（`MessageCircle` 小图标 + 问题文本，truncate），右侧标签显示「追问」（替代 自动/手动），latency / 已停止 等后缀不变
- 覆盖句子的取词（现有的 `「{utterance quote}」`）对 follow-up 卡不显示
- waiting / streaming / 思考过程 / error 渲染全部复用现有分支
- 悬浮高亮（TranscriptPanel 按 `fromId..toId` 高亮）自动生效，无需改动

### 6. `src/main/save-conversation.ts` — 自动保存记录

`formatConversation` 对 follow-up 卡：round 标签用 `**追问**`（沿用 已停止/未写完 变体），问题文本以引用或加粗行呈现，答案正文照旧；排序已按 `toId` 无需改动。

## 不做的事

- 无新快捷键（按钮触发，与截图模式一致）→ 不动 `CustomShortcuts.tsx` / `help/Shortcuts.tsx` / shortcuts store
- 悬浮工具栏不加追问入口（需要键盘输入，toolbar 是 `focusable: false` 的鼠标窗口）
- 追问问答不进入后续提示上下文（用户已确认）
- 渲染层 store 无需改动（卡片走既有 `upsertHint` / `conversation-hint-chunk` 事件流）

## 验证

1. `npm run typecheck` 通过
2. `npm run dev` 手动验证：
   - 对话模式听几句话 → 点「追问」输入问题 → 卡片流式生成，头部显示问题和「追问」标签
   - 追问流式中对方继续说话：追问卡不被撤回，新自动提示照常出（两者并行）
   - 追问流式中按「出提示」：生成普通提示卡，不覆盖追问卡
   - 「停止」/「清空对话」对追问卡生效；悬浮追问卡时左侧转写对应句子高亮
   - 无语音时直接追问可用（纯提问）
   - 开启「保存对话记录到本地」→ 检查 Markdown 文件中追问以 **追问** + 问题呈现
